# BUG-0014 美化界面拖拽范围自测清单

> 日期：2026-06-05
> 目标：美化界面仅空白区域触发窗口拖拽；按钮、控件、文本内容不触发拖拽，文本可选择复制。

## Phase 1：根因调查

- [x] 阅读 `HANDOFF.md`，确认当前任务上下文和既有 UI/测试约束。
- [x] 阅读 `BUG.md` 中 BUG-0014 的现象与期望。
- [x] 复盘用户二次反馈：导出成功后保存路径文字仍无法拖选，会触发窗口拖拽。
- [x] 复盘用户三次反馈：第二轮修复过头，美化界面所有区域无法拖拽；期望主预览区域和右侧边栏空白可拖，文本/按钮不可拖。
- [x] 阅读 `.codex/rules/` 和 `reference/ui/ui_spec.md`、`reference/ui/ui-migration-spec.md`，确认拖拽区域与前端测试规范。
- [x] 搜索 `data-tauri-drag-region`、`selectstart`、`mousedown` 等入口，定位拖拽触发链路。
- [x] 确认工作树中 `BUG.md` 已有用户新增 BUG-0014 内容，后续只做追加式更新。

## Phase 2：模式分析

- [x] 对比 UI 规范中旧的“全局禁用文本选中”要求与 BUG-0014 的“文本可选择复制”新期望。
- [x] 确认当前拖拽监听使用 `closest('[data-tauri-drag-region]')`，会把根拖拽区域的所有非交互后代视为可拖拽。
- [x] 确认可交互元素过滤只能保护按钮/控件，无法保护普通文本节点。
- [x] 确认第一轮遗漏：真实 Tauri WebView 会原生识别 `data-tauri-drag-region="deep"`，不受程序化监听的 `hasAttribute()` 过滤影响。
- [x] 对比参考 UI：预览页参考实现只在局部 header 上放拖拽区域，不在整页根容器使用 `deep`。
- [x] 确认第二轮过修复：自定义拖拽标记仍在预览页根节点上，但用户实际点击命中的是主预览/右侧边栏内容容器。
