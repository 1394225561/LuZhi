# Phase 2 / W3-W4 自测清单：Windows 捕获预研与双音频链路

## 目标

验证音频时间戳模型、系统音频和麦克风混音原型可行，并完成 Windows DXGI/WASAPI 的最小可行性样例。

## 环境检查

- [ ] macOS 测试机可采集系统音频和麦克风。
- [ ] Windows 测试机可运行 DXGI 捕获样例。
- [ ] Windows 测试机可运行 WASAPI loopback 样例，或明确记录失败设备和原因。
- [ ] 麦克风设备列表可枚举。

## 功能验证

- [ ] 系统音频可生成 `AudioChunk`。
- [ ] 麦克风可生成 `AudioChunk`。
- [ ] 系统音频和麦克风可混音为连续 `MixedAudioChunk`。
- [ ] 输出视频文件包含音轨。
- [ ] Windows 录屏或音频样例至少完成单独验证。

## 时间戳与同步

- [ ] 视频帧、系统音频、麦克风使用同一 `MediaTimestamp` 模型。
- [ ] 音频采样率不一致时能重采样或显式报错。
- [ ] 音频短缺区间能静音填充。
- [ ] 音频重叠区间能混音且不爆音。

## 架构验证

- [ ] DXGI 代码隔离在 `platform/windows` 边界内。
- [ ] WASAPI 代码隔离在 `platform/windows` 边界内。
- [ ] cpal 麦克风采集通过 Trait 接入。
- [ ] Windows 平台差异通过 `capabilities()` 暴露。

## 风险验证

- [ ] Windows 系统音频不可用时有 Plan B 记录。
- [ ] 管理员权限窗口捕获限制有中文提示方案。
- [ ] 音画同步偏差有测量方法。

## 测试要求

- [ ] 音频时间戳对齐有单元测试。
- [ ] 静音填充有单元测试。
- [ ] 不同采样率输入有测试覆盖。

## 人工审查

- [ ] WASAPI/DXGI unsafe 或 FFI 代码已人工审查。
- [ ] 音频缓冲没有无界增长。
- [ ] 没有在测试中调用真实录屏 API。
