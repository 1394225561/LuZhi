# 项目研发任务启动书

## 角色设定

请你扮演一位拥有 10 年以上经验的资深桌面端技术架构师。你精通 Rust、Tauri 2.0、跨平台音视频底层捕获（ScreenCaptureKit/DXGI/WASAPI）以及 FFmpeg 工程化实践。你在高并发音视频流处理、极低延迟渲染以及跨平台架构抽象方面有丰富的实战经验。

## 任务目标

基于我提供的初期 PRD（**PRD 文件路径："docs/PRD/LuZhi_PRD_final_version.md"**），为我设计一份详尽、专业、可直接指导研发落地的【系统架构设计】与【开发执行计划】。

## 输入上下文

1. 项目定位：中国版 Screen Studio，核心做“录屏 + AI 自动美化 + 一键导出”，极致单点，砍掉一切非核心功能（无字幕、无模板、无协作）。
2. 技术栈：Tauri 2.0 + React (TS + Tailwind) + Rust 底层 + FFmpeg。
3. **约束条件**：请严格遵循我已制定的项目约束规则（特别是架构分层、数据流红线、AI 与人协作边界等规定），以及 .codex/rules/ 目录下的规则分流文件。

## 核心输出要求

请按以下结构输出你的架构与计划方案，要求越具体越好，拒绝假大空，必须包含技术选型理由、数据流向、模块交互方式及风险兜底策略：

### 一、 深度系统架构设计

1. **进程与线程模型** ：Tauri 主进程、核心录制线程、视频处理线程、UI 渲染进程的协同模型。如何避免录制和 AI 美化处理阻塞主事件循环？
2. **跨平台抽象层设计** ：请给出 Rust 侧的核心 Trait 定义（如 `ScreenCapture` 、 `AudioCapture` 、 `VideoProcessor` ），说明 macOS 和 Windows 的底层实现如何通过 Trait 隔离，并确保扩展性。
3. **核心数据流设计（重点）** ：请详细描绘从“屏幕像素/系统音频捕获” -> “内存缓冲” -> “AI 美化处理（光标/裁剪）” -> “FFmpeg 编码封装” 的完整数据流向。必须说明：
   - 采用何种机制（如 Ring Buffer、共享内存、无锁队列）解决捕获端与消费端的速率差？
     - 视频帧在 Rust 与 FFmpeg 之间如何零拷贝或高效传递？
     - 系统音频与麦克风在 Rust 侧如何做时间戳对齐与混音？

### 二、 关键技术攻坚与预研方案

针对 PRD 中的技术难点，给出具体的工程级解法：

1. **光标平滑与放大引擎** ：贝塞尔插值算法如何在视频帧流中实现？移动平均滤波的窗口大小如何自适应帧率？点击放大效果的状态机如何设计？
2. **空白段自动裁剪** ：音频 RMS 阈值检测与帧差分算法的具体实现思路？如何设定时间窗口来区分“用户思考”和“真空白”？如何生成裁剪时间线供 FFmpeg 执行？
3. **4K 性能保障** ：在 MVP 阶段如何利用硬件加速（Metal/DX12）处理视频流？如果 GPU 不可用，降级策略是什么？

### 三、 细化研发执行计划（MVP 阶段 W1-W12）

请将 PRD 中的里程碑拆解为具体的工程任务，要求：

1. 以周为单位，明确每周的 **研发重点、交付物、以及模块间的依赖关系** 。
2. 标出关键的“集成风险点”及应对措施（如 W3-4 双平台音频捕获极易翻车，需准备 Plan B）。
3. 明确前端 UI 与 Rust 底层的联调节奏。

### 四、 架构演进建议

基于 MVP 的架构设计，说明 V2 阶段（背景模糊、自动缩放关键区域）需要怎样的架构预留？当前设计应避免哪些“过度设计”？

### 产物落地

将最终的产物落地到 "docs/architecture/project-architecture-and-overall-planning.md" 文件中。

## 注意事项

- 你的方案将直接作为团队的唯一开发蓝图，请确保方案的工程可行性。
- 重点考虑 Rust 在音视频处理中的内存安全与性能平衡，避免不必要的数据拷贝。
- 紧扣“录屏+美化”的核心，不要发散到 PRD 砍掉的功能上。
