# 方向一：中国版 Screen Studio —— "录屏 + AI 剪辑"极致单点

> 产品 PRD v1.0 的方向性演化建议。

---

## 第一部分：方向深挖

### 产品具体长什么样？

**核心功能只有三个：**

1. **录制** —— 全屏/窗口/区域，1080p/4K，系统音频 + 麦克风。不需要花哨功能，稳定、清晰就行。参考 Screen Studio 的录制体验：录完直接在 App 内预览，不需要导出再看。

2. **AI 自动美化** —— 这是你的唯一差异化，必须做到极致：
   - 光标放大 + 平滑轨迹（Screen Studio 的核心卖点，你必须做到同等水平）
   - 自动裁剪空白段（录屏时发呆、等加载的片段）
   - 自动缩放关键区域（点击菜单时自动放大菜单区域，输入命令时自动放大终端区域）
   - 背景自动模糊/纯色（把桌面壁纸变成干净的纯色背景）
   - 自动加圆角窗口边框（让视频看起来像产品官网的 GIF 演示）

3. **一键导出** —— 预设好 B 站（16:9, 1080p）、抖音（9:16, 竖屏裁剪）、小红书（1:1）的导出格式。不是"分发"——只是格式转换和下载。用户自己上传，不要碰平台 API 这个雷区。

**字幕？不做。** 剪映的字幕已经免费且足够好，你做字幕是拿短板打别人的长板。如果用户需要字幕，导出后丢进剪映就行。你只做"录完就出成品"这个场景。

**摘要？不做。** 知识库？不做。模板系统？不做。团队协作？不做。**全部砍掉。**

## 第二部分：执行细节

### 1. 技术架构

#### 技术栈选型

| 层级                | 选型                                | 理由                                                          |
| ------------------- | ----------------------------------- | ------------------------------------------------------------- |
| 桌面框架            | Tauri 2.0                           | 跨平台（Windows + macOS），包体小（~10MB），性能优于 Electron |
| 前端 UI             | React + TypeScript + Tailwind CSS   | 生态成熟，组件库丰富（shadcn/ui），开发效率高                 |
| 录制引擎（macOS）   | ScreenCaptureKit                    | Apple 原生 API，性能最优，支持系统音频捕获                    |
| 录制引擎（Windows） | DXGI Desktop Duplication + WASAPI   | Windows 原生方案，低延迟，支持系统音频                        |
| 视频处理            | FFmpeg（Rust binding: ffmpeg-next） | 行业标准，裁剪/转码/格式转换一站式解决                        |
| 光标美化            | Rust 原生实现 + GPU 加速            | 光标轨迹平滑（贝塞尔插值）、放大动画需要高性能渲染            |
| 视频编码            | H.264 (libx264) / H.265 (libx265)   | 兼容性好，H.265 在同等画质下文件更小                          |
| 音频处理            | FFmpeg + cpal（Rust 音频库）        | 系统音频 + 麦克风混音                                         |
| 自动更新            | Tauri Updater                       | 内置自动更新机制，支持增量更新                                |
| 崩溃报告            | Sentry (Tauri SDK)                  | 生产环境错误监控                                              |
| 分析统计            | PostHog (self-hosted)               | 用户行为分析，隐私友好，可自托管                              |

#### 核心模块划分

```
┌─────────────────────────────────────────────────┐
│                    LuZhi App                      │
├─────────────┬─────────────┬─────────────────────┤
│  UI Layer   │  App Logic  │   Native Modules    │
│  (React)    │  (Rust)     │   (Rust/FFI)        │
├─────────────┼─────────────┼─────────────────────┤
│ 录制控制面板  │ 录制状态机    │ ScreenCaptureKit   │
│ 预览播放器   │ 视频处理管线   │ DXGI Desktop Dup   │
│ 导出对话框   │ 光标美化引擎   │ WASAPI 音频捕获     │
│ 设置页面     │ 空白段检测器   │ FFmpeg 编解码       │
│ 激活/授权    │ 导出格式转换   │ 系统权限管理        │
└─────────────┴─────────────┴─────────────────────┘
```

#### 关键技术难点

| 难点                    | 具体挑战                                   | 解决思路                                                              |
| ----------------------- | ------------------------------------------ | --------------------------------------------------------------------- |
| 系统音频捕获（macOS）   | macOS 对系统音频捕获有严格限制             | 使用 ScreenCaptureKit 的 `SCShareableContent` API，macOS 13+ 原生支持 |
| 系统音频捕获（Windows） | 需要 WASAPI loopback 模式                  | 使用 `wasapi-rs` crate，需要处理不同音频设备的兼容性                  |
| 光标轨迹平滑            | 原始光标坐标有抖动，直接使用会导致动画卡顿 | 贝塞尔曲线插值 + 移动平均滤波，窗口大小 5-10 帧                       |
| 空白段检测              | 需要区分"用户在思考"和"真正的空白"         | 音频静音检测（RMS 阈值）+ 画面变化检测（帧差分）双重判断              |
| 4K 视频实时处理         | 4K@60fps 的数据量巨大                      | 使用 GPU 加速（Metal on macOS, DX12 on Windows）做渲染，CPU 只做编排  |
| 跨平台一致性            | macOS 和 Windows 的录屏 API 行为差异       | 抽象统一的录制接口层，平台差异封装在 Native Modules 中                |

### 2. MVP 功能清单

#### 包含（Must Have）

| 功能              | 说明                               | 复杂度 |
| ----------------- | ---------------------------------- | ------ |
| 全屏录制          | 1080p/4K，30fps/60fps              | 中     |
| 窗口录制          | 选择目标窗口录制                   | 中     |
| 区域录制          | 拖拽选择矩形区域，最小 320x240     | 低     |
| 系统音频录制      | macOS + Windows 双平台             | 高     |
| 麦克风录制        | 设备选择 + 音量调节                | 低     |
| 光标放大          | 点击时自动放大光标区域，可配置倍数 | 高     |
| 光标轨迹平滑      | 贝塞尔曲线平滑光标移动             | 中     |
| 自动裁剪空白段    | 检测静音 + 无操作片段，一键裁剪    | 中     |
| 导出 16:9 (1080p) | 标准 B 站/YouTube 格式             | 低     |
| 导出 9:16 (1080p) | 竖屏格式，智能居中裁剪             | 中     |
| 导出 1:1 (1080p)  | 正方形格式                         | 低     |
| 14 天试用         | 全功能试用，到期后锁定             | 低     |
| 激活码授权        | 买断后输入激活码解锁               | 低     |

#### 砍掉（不做）

| 功能             | 砍掉理由                |
| ---------------- | ----------------------- |
| 模板系统         | 过度设计，先不做        |
| 快捷键叠加       | P2 功能，MVP 不需要     |
| 背景美化         | 好功能但非核心，V2 再做 |
| 自动缩放关键区域 | 技术难度高，V2 再做     |

### 3. 开发里程碑

#### 阶段一：MVP（0-3 个月）

| 周次   | 交付物                                   | 验证方式                                      |
| ------ | ---------------------------------------- | --------------------------------------------- |
| W1-2   | Tauri 项目脚手架 + 录制引擎原型（macOS） | 能录出一个 mp4 文件                           |
| W3-4   | 录制引擎 Windows 适配 + 音频捕获         | 双平台都能录屏 + 录音                         |
| W5-6   | 录制 UI（模式选择、参数配置、录制控制）  | 完整的录制流程可用                            |
| W7-8   | 光标放大 + 轨迹平滑                      | 录出的视频光标效果达到 Screen Studio 80% 水平 |
| W9-10  | 空白段检测 + 自动裁剪                    | 5 分钟视频裁剪后 < 3 分钟                     |
| W11-12 | 导出模块（16:9/9:16/1:1）+ 授权系统      | 可导出三种格式，试用/激活码可用               |

**阶段一目标：** 内部可用的 MVP，可以发给 20 个种子用户测试。

#### 阶段二：打磨 + 上线（3-6 个月）

| 周次   | 交付物                                   | 验证方式                             |
| ------ | ---------------------------------------- | ------------------------------------ |
| W13-14 | 种子用户反馈收集 + Bug 修复              | 20 个种子用户 NPS > 40               |
| W15-16 | UI/UX 打磨 + 性能优化                    | 4K@30fps 录制不掉帧，导出速度 < 实时 |
| W17-18 | 自动更新 + 崩溃报告 + 使用统计           | 端到端更新流程可用                   |
| W19-20 | 营销素材准备（官网、演示视频、社区帖子） | 官网上线，3 个平台发布内容           |
| W21-24 | 公开 Beta + 社区运营 + 持续迭代          | 500 个注册用户，100 个活跃用户       |

**阶段二目标：** 产品公开上线，开始获客。

#### 阶段三：增长（6-12 个月）

| 月份   | 交付物                                     | 验证方式                     |
| ------ | ------------------------------------------ | ---------------------------- |
| M7-8   | 背景美化（纯色/模糊）+ 自动圆角窗口        | 用户反馈 + 使用率统计        |
| M9-10  | 自动缩放关键区域（菜单放大、终端放大）     | 功能使用率 > 30%             |
| M11-12 | Windows 平台打磨 + 性能优化 + 高级导出选项 | Windows 用户留存率追平 macOS |

**阶段三目标：** 功能追平 Screen Studio 核心体验，用户稳定增长。

### 6. 风险应对矩阵

| 风险                   | 概率 | 影响 | 应对方案                                                                     |
| ---------------------- | ---- | ---- | ---------------------------------------------------------------------------- |
| 4K 性能不达标          | 中   | 高   | MVP 先只支持 1080p，4K 作为 V2 目标；如果用户 4K 需求强烈，优先投入 GPU 加速 |
| macOS 屏幕录制权限问题 | 低   | 中   | 提供详细的权限引导流程，首次启动时自动检测并引导用户授权                     |
| Windows 音频捕获兼容性 | 高   | 中   | 测试主流声卡驱动，提供"降级模式"（仅麦克风，不录系统音频）                   |
