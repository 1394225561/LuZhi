## 1. 产品概述与核心目标

### 1.1 产品定位

录智（LuZhi）是一款 AI 驱动的视频内容生产平台，面向中国市场，提供从屏幕录制到多平台分发的全链路自动化能力。产品定位为"不是更好的录屏工具，而是 AI 视频内容工厂"。

- **产品名称：** 录智（LuZhi）
- **一句话介绍：** 录一次，AI 搞定一切——自动剪辑、字幕、摘要、一键分发全平台的视频内容生产平台
- **技术路线：** v1 采用 Tauri 跨平台框架实现 Windows + macOS 双端，基础 AI 功能（字幕、裁剪）使用本地轻量模型，高级功能（摘要、翻译）调用云端 API

### 1.2 成功指标

| 指标 | 目标值 | 衡量周期 | 说明 |
|---|---|---|---|
| 月活跃用户数（MAU） | 上线 6 个月达到 50,000 | 月 | C 端引流层规模指标 |
| 视频生产耗时缩短比 | ≥ 70%（从 30 分钟降至 9 分钟以内） | 单次操作 | 对比 OBS + 剪映手动流程 |
| 付费转化率 | 免费用户 → 专业版 ≥ 5% | 月 | 订阅制核心变现指标 |
| 知识库采用率 | B 端客户启用知识库功能 ≥ 60% | 季度 | 差异化功能验证 |
| 平台覆盖数 | 支持 ≥ 4 个分发平台（B站/抖音/小红书/微信视频号） | 版本 | 一键分发能力完整性 |

### 2.3 角色升降级规则

- `free_user` → `pro_user`：用户完成支付后自动升级，订阅到期未续费降级为 `free_user`（宽限期 7 天，期间保留专业版权限）
- `free_user` / `pro_user` → `team_member`：接受团队管理员邀请后获得 `team_member` 角色，原角色保留（双角色共存）
- `pro_user` → `team_admin`：购买团队版后获得 `team_admin` 角色，原 `pro_user` 角色保留
- 任何角色 → 封禁状态：系统管理员执行封禁操作，用户所有功能不可用，已有数据保留 90 天后清除

## 4. 功能模块详细设计

### 4.1 全平台屏幕录制（P0）

**业务目标：** 提供 Windows + macOS 双平台原生屏幕录制能力，支持全屏、窗口、区域三种录制模式，捕获系统音频和麦克风音频。

**触发条件：**
- 用户在主界面点击"开始录制"按钮
- 用户使用全局快捷键（默认 `Ctrl+Shift+R` / `Cmd+Shift+R`）触发录制

**主流程：**

1. **选择录制范围** → 用户选择三种模式之一：
   - 全屏录制：自动获取主显示器分辨率
   - 窗口录制：用户点击目标窗口，系统捕获该窗口句柄
   - 区域录制：用户拖拽选择矩形区域，最小尺寸 320x240 像素
2. **配置录制参数** → 用户设置：
   - 分辨率：720p（免费用户）/ 1080p / 4K（付费用户）
   - 音频源：系统音频（开/关）+ 麦克风（开/关 + 设备选择）
   - 帧率：30fps（默认）/ 60fps（付费用户可选）
   - 光标显示：显示/隐藏系统光标
3. **创建视频记录** → 调用 `POST /api/v1/videos` 创建 status=recording 的 Video 记录
4. **启动录制进程** → 本地调用系统级录屏 API（macOS: ScreenCaptureKit / Windows: DXGI Desktop Duplication）
5. **录制中** → 实时显示录制时长计时器、暂停/继续按钮、停止按钮
6. **暂停/继续** → 用户点击暂停，录制进程暂停写入但保留资源；点击继续恢复
7. **停止录制** → 用户点击停止或按快捷键 → 录制进程停止 → 视频文件写入本地临时目录
8. **上传与状态更新** → 视频文件上传至存储服务 → Video.status 变更为 `uploading` → 上传完成后变更为 `ready`

**状态机流转：**

```
[无] + 用户点击录制 → [recording]
[recording] + 用户点击暂停 → [paused]
[paused] + 用户点击继续 → [recording]
[recording] + 用户点击停止 → [uploading]
[uploading] + 上传成功 → [ready]
[uploading] + 上传失败（重试 3 次后仍失败） → [failed]
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 免费用户超出月度限额 | `free_user` 且 `monthly_video_count ≥ 10` | 拒绝录制，弹窗提示"本月录制次数已用完，升级专业版解锁无限录制" | `40001` |
| 免费用户选择高分辨率 | `free_user` 选择 1080p 或 4K | 分辨率选项置灰，tooltip 显示"专业版解锁高清录制" | `40002` |
| 录制区域过小 | 用户选择区域 < 320x240 | 提示"录制区域最小为 320×240 像素，请重新选择" | `40003` |
| 屏幕录制权限未授予（macOS） | 系统未授权屏幕录制权限 | 引导用户打开"系统设置 → 隐私与安全性 → 屏幕录制"并授权 | `40004` |
| 磁盘空间不足 | 可用空间 < 500MB | 提示"磁盘空间不足，请清理后重试" | `40005` |
| 录制过程中窗口被关闭 | 目标窗口被关闭（窗口录制模式） | 自动暂停录制，提示"目标窗口已关闭，请选择其他窗口或停止录制" | `40006` |
| 麦克风被占用 | 其他应用占用麦克风 | 提示"麦克风正被其他应用使用，请关闭后重试"，允许仅录制系统音频继续 | `40007` |

### 4.2 AI 自动后处理引擎（P0）

**业务目标：** 录制完成后，AI 自动执行去空白段、平滑光标运动、智能裁剪、添加转场，消除人工剪辑环节。

**触发条件：**
- 录制完成且 Video.status 变为 `ready` 后自动触发（用户可在设置中关闭自动触发）
- 用户在视频详情页手动点击"AI 后处理"按钮

**主流程：**

1. **接收输入** → 读取原始视频文件 + 录制元数据（光标轨迹、点击事件、窗口焦点变化时间戳）
2. **分析视频内容** → AI 模型执行以下分析：
   - 静默检测：识别连续无操作 > 3 秒的片段，标记为"空白段"
   - 光标轨迹分析：识别鼠标移动路径，标记需要放大的点击位置
   - 画面变化检测：识别窗口切换、页面跳转、Tab 切换等产生画面显著变化的关键帧（相邻帧像素差异 > 30% 判定为关键帧）
3. **生成处理方案** → 输出一份 JSON 格式的编辑决策列表（EDL），包含：
   - 需要删除的空白段时间范围（start_ms, end_ms）
   - 需要添加光标放大的时间点和区域
   - 需要添加转场的位置和类型
4. **用户确认/调整** → 在时间轴上展示处理方案预览，用户可以：
   - 接受全部建议
   - 逐条取消某些建议
   - 手动调整空白段裁剪边界
5. **执行处理** → 根据最终确认的 EDL 执行视频处理：
   - 裁剪空白段
   - 平滑光标轨迹（贝塞尔曲线插值）
   - 在关键帧位置添加转场效果
   - 光标点击位置添加放大动画
6. **输出结果** → 生成处理后的新视频文件 → 更新 Video 记录（ai_processed=true）

**状态机流转：**

```
[ready] + 自动触发或手动触发 → [processing]
[processing] + 分析完成，等待用户确认 → [pending_review]
[pending_review] + 用户确认 → [processing]
[pending_review] + 用户取消 → [ready]
[processing] + 处理完成 → [ready]（ai_processed=true）
[processing] + 处理失败 → [ready]（ai_processed=false，保留原始视频）
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 视频过短 | duration < 5 秒 | 提示"视频时长不足 5 秒，无需 AI 处理" | `40101` |
| AI 模型加载失败 | 本地模型文件损坏或缺失 | 提示"AI 处理组件异常，请重新安装应用" | `40102` |
| 处理超时 | 处理时间 > 10 分钟 | 自动终止处理，保留已处理部分，提示"处理超时，已保存当前进度" | `40103` |
| 用户取消处理 | 用户在处理过程中点击取消 | 立即停止处理进程，保留原始视频，Video.status 回退为 ready | — |
| 存储空间不足 | 处理后文件写入失败 | 清理临时文件，提示"存储空间不足，无法保存处理结果" | `40005` |

### 4.3 AI 字幕与摘要生成（P0）

**业务目标：** 自动将视频语音转为文字字幕（支持中英文混合），并生成视频内容摘要和关键词。

**触发条件：**
- 视频 status 变为 `ready` 且 `ai_processed=true` 后自动触发
- 用户在视频详情页手动点击"生成字幕"或"生成摘要"按钮

**主流程（字幕生成）：**

1. **提取音频** → 从视频文件中分离音轨，转为 16kHz 单声道 WAV 格式
2. **语音识别** → 调用 ASR 模型（Whisper 或本地中文模型）进行语音转文字
   - 输入：音频文件
   - 输出：带时间戳的文字片段数组
3. **语言检测** → 自动识别语言（中文/英文/中英混合），选择对应识别模型
4. **文本后处理** → 对识别结果执行：
   - 去除口语化填充词（"嗯"、"啊"、"那个"）
   - 标点符号补全
   - 句子合并（短句合并为合理长度的字幕段，每段 ≤ 200 字符）
5. **生成字幕文件** → 按 SRT 和 VTT 双格式输出 → 存储并关联到视频
6. **用户校对** → 在字幕编辑器中展示，用户可逐条修改文字和时间戳

**主流程（摘要生成）：**

1. **获取字幕文本** → 读取已生成的字幕完整文本
2. **调用 LLM** → 将字幕文本发送至 LLM，Prompt 指令：
   - 生成 50-500 字的中文摘要
   - 提取 3-10 个关键词
   - 输出 JSON 格式：`{"summary": "...", "keywords": [...]}`
3. **存储结果** → 创建 Summary 记录，关联到视频

**状态机流转（字幕）：**

```
[无] + 触发生成 → [generating]
[generating] + 识别完成 → [generated]
[generated] + 用户编辑 → [edited]
[generating] + 识别失败 → [failed]
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 视频无音频 | 音频轨道为空 | 跳过字幕生成，提示"视频未检测到音频，无法生成字幕" | `40201` |
| 音频质量过差 | 信噪比低于 15dB | 继续生成但标记 `confidence=low`，提示"音频质量较差，字幕准确率低于 80%，请人工校对" | `40202` |
| 语言不支持 | 检测到非中/英语言 | 提示"当前仅支持中文和英文语音识别" | `40203` |
| LLM 调用失败（摘要） | 网络超时或 API 错误 | 重试 2 次（间隔 5 秒），仍失败则提示"摘要生成失败，请稍后重试" | `40204` |
| 免费用户调用摘要功能 | `free_user` 调用摘要生成 | 提示"AI 摘要为专业版功能，请升级" | `40205` |
| 翻译功能（专业版） | 用户点击"翻译字幕" | 调用翻译 API 将字幕翻译为目标语言，生成新字幕记录，language 字段为目标语言 | — |

### 4.4 一键多平台分发（P1）

**业务目标：** 将一个视频自动适配 B 站（16:9）、抖音（9:16）、小红书（1:1）、微信视频号（3:4）的格式要求，一键发布。

**触发条件：**
- 用户在视频详情页点击"一键分发"按钮
- 用户选中多个视频后批量点击"一键分发"

**主流程：**

1. **选择目标平台** → 用户勾选目标平台（可多选）：B 站 / 抖音 / 小红书 / 微信视频号
2. **配置各平台参数** → 系统根据平台自动填充默认值，用户可调整：
   - B 站：标题、描述、标签、分区、封面
   - 抖音：标题、话题标签、封面
   - 小红书：标题、描述、标签、封面
   - 微信视频号：标题、描述
3. **创建分发任务** → 为每个目标平台创建一条 DistributionTask 记录，status=pending
4. **视频格式转换** → 按各平台要求的分辨率和比例进行视频裁剪/缩放：
   - 16:9 → 直接使用原视频（如果原视频是 16:9）
   - 9:16 → 智能裁剪：以画面中心为焦点，裁剪为竖屏比例，AI 识别关键内容区域确保不被裁掉
   - 1:1 → 以画面中心裁剪为正方形
   - 3:4 → 以画面中心裁剪
5. **字幕位置适配** → 根据目标比例重新计算字幕位置和字号
6. **上传发布** → 调用各平台开放 API 上传视频 → DistributionTask.status 变更为 uploading → 上传完成后变更为 published
7. **返回结果** → 展示各平台发布状态和链接

**状态机流转：**

```
[pending] + 开始处理 → [processing]
[processing] + 格式转换完成 → [uploading]
[uploading] + 平台返回发布成功 → [published]
[uploading] + 平台返回失败且 retry_count < 3 → [uploading]（retry_count + 1）
[uploading] + 平台返回失败且 retry_count ≥ 3 → [failed]
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 平台授权过期 | 平台 OAuth token 失效 | 提示"平台授权已过期，请重新授权"，引导用户重新登录授权 | `40301` |
| 视频时长超出平台限制 | 抖音要求 ≤ 15 分钟 | 提示"抖音平台视频时长上限为 15 分钟，当前视频为 X 分钟" | `40302` |
| 视频文件超出平台大小限制 | 平台文件大小限制 | 提示"视频文件超过平台限制，请压缩后重试" | `40303` |
| 智能裁剪丢失关键内容 | AI 无法识别关键内容区域 | 回退为居中裁剪，提示"自动裁剪未覆盖所有重要内容，请预览确认" | `40304` |
| 部分平台发布失败 | 多平台分发时部分失败 | 展示各平台独立状态，失败平台显示错误原因和重试按钮 | — |
| 免费用户调用分发功能 | `free_user` | 提示"一键多平台分发为专业版功能，请升级" | `40305` |

### 4.5 光标放大与高亮（P1）

**业务目标：** 在教程视频中，用户点击时自动放大光标区域并高亮显示，让观众清晰看到操作细节。

**触发条件：**
- 录制开始时，如果用户在设置中启用了"光标放大"功能
- AI 后处理阶段自动识别点击事件并添加放大效果

**主流程：**

1. **录制阶段：捕获光标事件** → 本地录制进程实时记录：
   - 光标位置坐标（x, y）每帧记录
   - 鼠标点击事件（左键/右键/中键）及时间戳
   - 滚轮事件及时间戳
2. **后处理阶段：识别高亮点** → AI 分析光标轨迹，标记需要放大的位置：
   - 识别所有鼠标点击事件
   - 识别鼠标悬停 > 2 秒的位置（用户在查看某个元素）
3. **生成放大动画** → 对每个标记点：
   - 以点击位置为圆心，截取半径 150 像素的区域
   - 在点击前 0.3 秒开始放大动画，放大倍数 2.0 倍（可配置 1.5-4.0）
   - 保持放大 1.5 秒后缩小回原尺寸
   - 放大区域添加圆形高亮边框（默认白色，3px 宽度）
4. **叠加到视频** → 将放大动画叠加到原始视频画面上

**状态机流转：**

```
[录制中] + 鼠标点击事件 → 记录点击时间戳和坐标
[后处理中] + 分析点击事件 → 生成放大动画方案
[后处理中] + 动画叠加完成 → 输出最终视频
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 光标被隐藏 | 用户在录制时隐藏了系统光标 | 跳过光标放大功能，提示"录制时未显示光标，无法添加放大效果" | `40401` |
| 放大区域超出画面 | 点击位置在画面边缘 | 自动调整放大区域中心，确保不超出画面边界 | — |
| 高频点击 | 连续快速点击（间隔 < 0.5 秒） | 合并相邻点击事件，只对最后一次点击添加放大效果 | — |
| 录制时未开启光标放大 | 功能未启用 | 后处理阶段不执行光标放大步骤，其他后处理功能正常执行 | — |

### 4.6 视频内容知识库（P1）

**业务目标：** 将视频自动转为可搜索的文字内容，打标签建索引，让视频内容像文档一样可检索、可引用。

**触发条件：**
- 视频字幕生成完成后自动触发知识库索引构建
- 用户手动将已有视频添加到知识库

**主流程：**

1. **获取文字内容** → 读取视频的字幕全文（Subtitle.content）
2. **内容结构化** → AI 对转录文本执行：
   - 自动打标签：从内容中提取 3-5 个主题标签
   - 自动分类：根据内容判断分类路径（如"企业培训/财务/报销"）
   - 关键段落标记：标记包含关键操作步骤的时间点
3. **构建搜索索引** → 将转录文本写入 `search_vector` 字段（PostgreSQL `tsvector` 类型），支持中文全文搜索（使用 `zhparser` 分词插件）
4. **关联元数据** → 创建 KnowledgeEntry 记录，关联视频、用户、团队、标签、分类
5. **搜索与展示** → 用户在知识库页面输入关键词：
   - 执行全文搜索，返回匹配的视频列表
   - 每条结果展示：视频标题、匹配片段（高亮关键词）、时间戳（点击跳转到视频对应位置）
   - 支持按标签、分类、时间范围过滤

**状态机流转：**

```
[无字幕] + 字幕生成完成 → [indexing]
[indexing] + 索引构建完成 → [indexed]
[indexing] + 索引构建失败 → [failed]
[indexed] + 字幕内容更新 → [reindexing]
[reindexing] + 索引更新完成 → [indexed]
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 字幕不存在 | 视频未生成字幕 | 提示"请先生成字幕后再添加到知识库" | `40501` |
| 搜索无结果 | 用户搜索的关键词无匹配 | 显示"未找到相关内容"，并推荐相关标签 | — |
| 分词器不可用 | zhparser 插件未安装或异常 | 降级为 `LIKE` 模糊查询，性能下降但功能可用，系统日志记录告警 | `40502` |
| 团队知识库容量超限 | 团队知识库条目数达到上限 | 提示"团队知识库已满，请删除不需要的条目或升级套餐" | `40503` |
| 重复添加 | 同一视频已存在于知识库 | 提示"该视频已在知识库中"，返回已有条目 | `40504` |

```
[active] + 成员主动退出 → [left]
```

### 4.9 键盘快捷键叠加（P2）

**业务目标：** 录制时实时显示用户按下的快捷键组合，教程视频中让观众清晰看到键盘操作。

**触发条件：**
- 用户在录制设置中启用"显示快捷键"功能
- 录制过程中用户按下键盘快捷键

**主流程：**

1. **启用功能** → 用户在录制设置中开启"显示快捷键"开关
2. **注册键盘钩子** → 录制进程注册全局键盘事件监听（低级别钩子，不拦截按键）
3. **捕获按键** → 记录每次按键事件：
   - 修饰键状态：Ctrl / Cmd / Shift / Alt
   - 普通键：字母键（A-Z）、数字键（0-9）、功能键（F1-F12）、方向键、空格键、回车键、Esc 键
   - 时间戳
4. **实时叠加显示** → 在录制画面右下角（可配置位置）显示按键提示：
   - 显示格式：`⌘ + C`（macOS）/ `Ctrl + C`（Windows）
   - 显示时长：按下后显示 2 秒后淡出
   - 样式：半透明黑色背景 + 白色文字，圆角矩形
5. **后处理整合** → 按键记录作为元数据保存，后处理时可调整显示样式或移除

**状态机流转：**

```
[录制中] + 按键事件 → [显示按键提示]
[显示按键提示] + 2 秒超时 → [淡出]
[淡出] + 动画完成 → [隐藏]
```

**异常与边界条件：**

| 异常场景 | 触发条件 | 系统行为 | 错误码 |
|---|---|---|---|
| 键盘钩子注册失败（macOS） | 未授予辅助功能权限 | 提示"请在系统设置中授予辅助功能权限" | `40801` |
| 快捷键与应用冲突 | 捕获的按键是应用自身快捷键 | 不拦截按键，正常传递给应用，仅做显示记录 | — |
| 高频按键 | 用户快速连续输入 | 限制显示频率：同一组合键 1 秒内只显示一次 | — |
| 多显示器场景 | 录制区域不包含叠加显示区域 | 自动将叠加显示区域调整到录制区域内 | — |

### 5.1 统一响应格式

所有 API 响应遵循以下格式：

```json
{
  "code": 0,
```
