# 历史录制侧栏 UI 重构设计

日期：2026-06-07

## 背景

当前 `src/components/recording-sidebar.tsx` 已实现历史录制列表能力，包括打开侧栏时加载录制记录、导入录制、删除录制、点击历史记录进入预览美化界面。用户反馈当前页面 UI 和交互不满意，希望在不改变现有功能逻辑的前提下重构历史录制列表界面。

本设计遵守项目 UI 规范中的 Raycast 近黑工具型风格，界面文字保持中文。历史录制属于录屏工具的辅助入口，应强调快速扫描、快速打开、低干扰删除。

## 目标

1. 将历史录制侧栏改为紧凑工具列表形态。
2. 保留现有功能逻辑：加载、导入、删除、点击记录跳转。
3. 提升列表项的扫描效率、hover 反馈和删除入口的清晰度。
4. 保持实现范围局限在 `recording-sidebar.tsx` 的界面结构和样式层。

## 非目标

1. 不修改 `listRecordings`、`importRecording`、`deleteRecording`、`onSelectRecording` 调用逻辑。
2. 不新增后端接口。
3. 不新增缩略图、搜索、分组、排序规则、确认弹窗或更多菜单。
4. 不改变历史记录点击后进入预览美化界面的业务流程。
5. 不引入新的 UI 组件库或新依赖。

## 已批准方向

采用 Raycast 风格的紧凑工具列表：

1. 侧栏宽度从 320px 调整为 360px。
2. 删除按钮默认隐藏，hover 或 focus-within 时显示。
3. 列表项保持紧凑行布局，不做媒体大卡片。
4. 不使用视觉伴随工具或浏览器 mockup。

## UI 设计

### 侧栏与开关

侧栏仍固定在屏幕右侧，打开关闭状态由现有 `isOpen` 控制。宽度调整为 360px，侧栏打开时外部历史按钮跟随移动到 `right-[360px]`。关闭时维持当前的右侧贴边按钮。

外部历史按钮继续使用 `History` 图标，不增加文字。按钮视觉改为更贴近工具浮层：近黑背景、细边框、hover 高亮、稳定尺寸，避免影响主录制面板。

### 顶部区域

顶部区域分两层：

1. 第一层：标题“历史录制”和关闭按钮。
2. 第二层：左侧显示记录数量，例如“共 3 条录制”；右侧为导入图标按钮。

导入按钮仍调用现有 `handleImport`，关闭按钮仍调用 `onToggle`。按钮使用图标和 `title` 提供含义，不新增额外文案按钮。

### 列表项

每条历史记录渲染为 56-64px 高的紧凑行：

1. 左侧：小型视频图标容器，使用 `Film` 图标。
2. 中部：主标题为 `formatDate(rec.createdAt)`，副信息为 `时长：formatDuration(rec.durationSecs)`。
3. 右侧：默认显示 `ChevronRight`，表示点击进入。
4. hover 或 focus-within 时：右侧切换为删除按钮。

列表项根元素继续绑定 `onClick={() => onSelectRecording(rec.id)}`。删除按钮继续在点击时 `stopPropagation()`，并调用现有 `handleDelete(rec.id)`。删除中仍根据 `deletingId === rec.id` 显示 `Loader2`。

### 状态呈现

加载态：居中显示 `Loader2` 和“加载历史录制...”，让用户知道侧栏正在读取数据。

空态：使用 `Film` 图标和两行中文文案：“暂无历史录制”“录制完成后会出现在这里”。不新增跳转或引导逻辑。

加载错误态：以边框提示块展示错误文本，保留现有 `loadError` 来源。

导入错误态：保留顶部错误 banner 的出现与自动消失逻辑，仅调整视觉层级，使其与侧栏边框、背景和文字大小一致。

## 交互约束

1. 点击记录必须继续跳转到对应历史录制的预览美化界面。
2. 点击删除按钮不得触发记录跳转。
3. 删除中按钮应 disabled，并显示 loading 图标。
4. hover 反馈只改变视觉表现，不改变列表数据。
5. focus-within 时也显示删除按钮，保证键盘聚焦时不会隐藏当前操作。
6. 所有按钮保持图标化，并通过 `title` 标明含义。

## 数据流

数据流保持现状：

1. `isOpen` 变为 true 时触发 `loadRecordings()`。
2. `loadRecordings()` 调用 `listRecordings()`，并按 `createdAt` 倒序写入 `recordings`。
3. 导入调用 `importRecording(selected)` 后刷新列表。
4. 删除调用 `deleteRecording(id)` 后从本地 `recordings` 状态移除对应条目。
5. 点击记录调用父组件传入的 `onSelectRecording(rec.id)`。

## 实现范围

预计只修改：

1. `src/components/recording-sidebar.tsx`

允许的改动类型：

1. 调整 JSX 层级。
2. 调整 Tailwind className。
3. 调整图标摆放和视觉状态。
4. 在不改变业务行为的前提下，补充纯 UI 派生文案，例如记录数量。

不允许的改动类型：

1. 修改 Tauri API 封装。
2. 修改父组件历史记录选择逻辑。
3. 修改排序、删除、导入、加载的行为语义。
4. 新增业务状态或后端调用。

## 验证方案

实现后需要执行：

1. TypeScript/前端构建验证。
2. 现有前端测试。
3. `git diff --check`。
4. 手动自测清单，覆盖侧栏打开、加载、空态、导入错误展示、点击记录跳转、hover 删除、删除 loading 和删除后列表更新。

本任务属于 UI-only 重构，不要求新增后端测试。若现有前端测试没有覆盖历史列表交互，可在实施计划阶段评估是否补充轻量组件测试；补测试不得改变业务逻辑。
