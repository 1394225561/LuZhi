# Phase 3 / W5-W6 实施计划：录制 UI 与前后端联调

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Phase 1/2 已完成的 macOS 录制闭环和双音频链路基础上，实现完整的中文录制控制面板、前后端 Tauri invoke/event 通信、真实系统权限检测、麦克风电平实时反馈、分辨率/FPS 参数选择。确保前端仅作为展示和命令层，录制状态机仍由 Rust 统一维护，视频帧/音频流不经过 JS。

**Architecture:** React UI 只负责命令下发和状态展示。Rust 端负责权限检测（真实 macOS API）、CaptureMode 扩展（全屏/窗口/区域）、MicLevelDetector（RMS 计算）、状态机守卫。通过 `mic-level` 事件和 `recording-tick` 事件向 UI 推送实时反馈。

**Tech Stack:** Tauri 2, React + TypeScript + Tailwind, Rust, ScreenCaptureKit, CoreGraphics (权限 API), AVFoundation (权限 API), cpal, Vitest, React Testing Library.

## Task 1: CaptureMode 扩展 Window/Area 变体

**目标**: Rust 后端接受全屏/窗口/区域三种模式参数，但窗口和区域的实际捕获逻辑预留。

**改动文件**: `src-tauri/src/core/config.rs`、`src-tauri/src/lib.rs`

### 1.1 `core/config.rs` — 枚举扩展

```rust

pub enum CaptureMode {
    FullScreen,
    Window,   // 新增：窗口录制（开发中）
    Area,     // 新增：区域录制（开发中）
}
```

- 为 `CaptureConfig` 补充解析辅助方法 `mode_from_str(s: &str) -> Result<CaptureMode, String>`
- 映射关系: `"fullscreen" → FullScreen`, `"window" → Window`, `"area" → Area`
- 未知字符串返回中文错误

### 1.2 `lib.rs` — `set_capture_mode` 命令

- 解析 payload.mode 字符串，使用 `mode_from_str` 转换为 `CaptureMode`
- 更新 `AppState` 中的 `capture_config.mode`

### 1.3 `lib.rs` — `start_recording` 命令

- 在调用 `MacRecordingService::start()` 之前，检查 `capture_config.mode`
- 若为 `Window` 或 `Area`：返回 `Err("窗口/区域录制模式正在开发中，当前仅支持全屏录制".to_string())`
- 不触发状态机迁移

## Task 2: MacPermissionProbe 接入真实 macOS API

**目标**: `recording_permissions` 命令返回真实系统权限状态，UI 根据状态显示中文引导。

**改动文件**: `src-tauri/src/platform/macos/permissions.rs`

### 2.1 屏幕录制权限检测

使用 CoreGraphics 框架的 `CGPreflightScreenCaptureAccess()`：

```rust
// FFI 声明（需人工审查）
extern "C" {
    fn CGPreflightScreenCaptureAccess() -> bool;
}
```

- 返回 `true` → `PermissionStatus::Granted`
- 返回 `false` → `PermissionStatus::NotDetermined`（注意：macOS 不提供「已拒绝」的直接检测，`CGPreflightScreenCaptureAccess` 仅表示是否需要弹权限请求）

**平台限制说明**: macOS 的 TCC 框架对屏幕录制权限的保护极强。`CGPreflightScreenCaptureAccess()` 返回 `false` 时，可能是「从未请求过」或「用户已拒绝」——两者无法直接用公开 API 区分。代码中需注释此限制。如需更精确判断，可在尝试创建 `SCStream` 时捕获权限错误，但那是 Phase 4+ 的行为。

### 2.2 麦克风权限检测

使用 AVFoundation 框架。有两种路径：

**路径 A (macOS 10.14+)**: `AVCaptureDevice.authorizationStatus(for: .audio)`
```objc
AVAuthorizationStatus status = [AVCaptureDevice authorizationStatusForMediaType:AVMediaTypeAudio];
```

**路径 B (macOS 14.0+)**: `AVAudioApplication.recordPermission`（仅 macOS 14+，不适用于向下兼容）

选用路径 A，因为 Tauri 2 支持 macOS 10.15+。使用 `objc2` crate 的 msg_send 进行调用：

```rust
use objc2::msg_send;
use objc2::rc::Retained;
use objc2_foundation::NSInteger;

// AVCaptureDevice 的 authorizationStatusForMediaType: 类方法
// 返回 AVAuthorizationStatus (NSInteger):
//   0 = NotDetermined
//   1 = Restricted
//   2 = Denied
//   3 = Authorized
```

### 2.3 状态映射

| 原生返回值 | PermissionStatus |
|-----------|-----------------|
| AVAuthorizationStatus == 3 / CGPreflight 返回 true | `Granted` |
| AVAuthorizationStatus == 2 (Denied) | `Denied` |
| AVAuthorizationStatus == 1 (Restricted) | `Denied`（无权限等同于拒绝） |
| AVAuthorizationStatus == 0 (NotDetermined) | `NotDetermined` |
| 其他非预期返回值 | `Unknown` |

### 2.4 非 macOS 平台

`#[cfg(not(target_os = "macos"))]` 时，`MacPermissionProbe` 的 `recording_permissions()` 继续返回 `Unknown`（与当前行为一致）。

### 验证

- `cargo test` 中 mock 验证状态映射逻辑
- `npm run tauri dev`：首次启动查看 System Preferences → Privacy → Screen Recording + Microphone，确认 UI 中权限状态与实际一致
- 授权前：UI 显示"屏幕录制权限未授权"引导文案
- 授权后：重启应用，UI 显示权限已授予

## Task 3: MicLevelDetector — RMS 电平计算器

**目标**: 实现一个纯算法模块，从麦克风 PCM 采样中计算归一化 RMS 电平值。

**改动文件**: `src-tauri/src/media/mic_level.rs` (新建)、`src-tauri/src/media/mod.rs`

### 3.1 数据结构

```rust
/// 基于滑动窗口的 RMS 电平检测器
pub struct MicLevelDetector {
    /// 最近 N 个采样的平方和
    squared_sum: f64,
    /// 滑动窗口中的采样数
    sample_count: usize,
    /// 窗口最大容量
    window_size: usize,
    /// 缓存最近一次计算的电平值 (0.0 ~ 1.0)
    current_level: f64,
}
```

### 3.2 公共接口

```rust
impl MicLevelDetector {
    /// 创建检测器，window_size 建议 1024~4096（对应 48kHz 下 21~85ms）
    pub fn new(window_size: usize) -> Self;

    /// 推入新的采样块，返回归一化电平值 0.0~1.0
    /// samples 为 f32 单声道或多声道交错的 PCM 采样
    pub fn push_samples(&mut self, samples: &[f32]) -> f64;

    /// 获取最近一次计算的电平值（不推入新数据）
    pub fn current_level(&self) -> f64;

    /// 重置检测器状态
    pub fn reset(&mut self);
}
```

### 3.3 RMS 计算算法

```
对每个采样 s：
  squared_sum = squared_sum + s²
  sample_count += 1
  若 sample_count >= window_size：
    rms = sqrt(squared_sum / sample_count)
    current_level = clamp(rms / REFERENCE_LEVEL, 0.0, 1.0)
    squared_sum = 0
    sample_count = 0
```

- `REFERENCE_LEVEL = 0.3`（经验值：f32 满幅 1.0 的 RMS 在典型语音下约 0.1~0.3）
- 归一化后超过 1.0 的值 clamp 到 1.0
- 空采样输入：`push_samples(&[])` 返回当前缓存值不变
- 零信号输入：所有采样为 0.0 时返回 0.0

### 3.4 线程安全

`MicLevelDetector` 设计为单线程使用（无 `Send + Sync`）。消费线程持有唯一实例，通过 `Arc<Mutex<f64>>` 或 `Arc<AtomicU64>` 将最新电平值暴露给事件发射线程。

### 验证

`#[cfg(test)] mod tests` 覆盖：

- 空输入 → 返回 0.0
- 全零信号 → 返回 0.0
- 满幅信号 (1.0) → 返回接近 1.0
- 半幅信号 (0.5) → 返回约 0.5
- 递增信号 → 电平值单调递增
- `reset()` 后 → `current_level()` 返回 0.0
- 窗口大小边界（1 个采样、8192 个采样）

## Task 4: 消费线程集成 MicLevelDetector + mic-level 事件推送

**目标**: 录制期间将麦克风实时电平值通过 `mic-level` Tauri 事件推送到前端。

**改动文件**: `src-tauri/src/platform/macos_service.rs`、`src-tauri/src/lib.rs`、`src-tauri/src/app/events.rs`

### 4.1 `app/events.rs` — 新增事件载荷

```rust
#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct MicLevelPayload {
    /// 归一化电平值 0.0 ~ 1.0
    pub level: f64,
}
```

### 4.2 `platform/macos_service.rs` — 集成 MicLevelDetector

- `MacRecordingService` 新增字段: `mic_level: Arc<Mutex<f64>>`（共享给事件发射线程）
- 在 `start()` 方法中创建 `MicLevelDetector::new(4096)`（约 85ms 窗口 @ 48kHz）
- 在消费线程的 `consume_frames()` 循环中：
  - 处理麦克风 `AudioChunk` 时，提取采样数据（需处理 f32/i16 格式转换）
  - 调用 `detector.push_samples(samples)`
  - 更新 `Arc<Mutex<f64>>` 共享值

### 4.3 `lib.rs` — mic-level 事件发射

- 在 `start_recording` 命令中，创建独立的 mic-level 推送线程
- 该线程每 100ms:
  - 读取 `Arc<Mutex<f64>>` 当前电平值
  - 调用 `app.emit("mic-level", MicLevelPayload { level })` 
  - 检查 `stop_flag` 是否被设置，若是则退出循环
- 线程句柄存储到 `AppState` 中（或复用 `TickRuntime` 的模式）
- 在 `stop_recording` 时销毁该线程

**备选方案**: 不创建独立线程，改为在 `TickRuntime` 中增加电平读取逻辑。但 `TickRuntime` 间隔为 250ms，mic 电平 100ms 更新率更流畅。评估后选择 100ms 独立线程（轻量、仅读取 Atomic/Mutex 值）。

### 验证

- `cargo test` 验证 MicLevelPayload 序列化格式正确
- `npm run tauri dev` 端到端：开始录制 → 对着麦克风说话 → 前端 mic 指示器实时变化
- 不说话时 mic 指示器接近 0，说话时明显上升

### 6.1 替换 mic 模拟为真实事件

移除：
```typescript
// 删除以下代码块
useEffect(() => {
  if (appState === 'recording' && micEnabled) {
    const interval = setInterval(() => {
      setMicVolume(Math.random() * 80 + 5)
```

```typescript

    }).then(fn => { unlisten = fn })

  return () => { unlisten?.() }
```

### 6.3 窗口/区域模式守护

```typescript
const handleStartRecording = useCallback(async () => {
  if (appState !== 'idle') return  // 防快速点击
  if (recordingMode !== 'fullscreen') {
    // 窗口/区域模式未实现，显示提示（不调用 Tauri）
    setErrorMessage('窗口/区域录制模式正在开发中，请使用全屏模式')
    return
  }
  setAppState('processing')
  try {
    await setCaptureMode({ mode: recordingMode, width: resolution.width, height: resolution.height, fps })
    await setAudioConfig({ captureSystemAudio: systemAudioEnabled, captureMicrophone: micEnabled, microphoneDevice: null, sampleRate: 48000, channels: 2 })
    await startRecording()
    // 状态切换由 recording-state-changed 事件驱动
  } catch (e) {
    setAppState('failed')
    setErrorMessage(String(e))
  }
}, [appState, recordingMode, resolution, fps, systemAudioEnabled, micEnabled])
```

### 6.5 状态转换加固

- `handleStartRecording`: 增加 `if (appState !== 'idle') return`
